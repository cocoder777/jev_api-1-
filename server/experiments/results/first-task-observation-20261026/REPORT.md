## 已验证的发送方式

1. 每个UDP报文长度40字节，二级信息单元标识均为0x0060。一个报文对应一个目标，艇与障碍物在同一通道逐目标发送。
2. 不是每秒一个包含所有目标的大报文。每个持续可见目标约每0.5秒更新一次，即约2Hz；全部目标合计形成每秒数十个小报文。
3. 本次头字段 `infoUnitSeq=1`、`infoUnitId=1`；它们没有提供本轮完整目标列表的数量或结束标记，不能拿它们拼装“每秒完整列表”。同一轮目标通常共享同一个报文时间戳，可用于离线对齐；接收顺序不等于固定原子快照。
4. 未收到目标删除、列表清空、障碍物新增等专用消息。目标不再被发送表现为该ID后续不再收到新态势。
5. 同一ID的新报文更新该目标的状态。已见4001～4007在本轮中的经纬度、速度、航向、类型、敌我属性和批号均不变；速度均为0，符合静态障碍物。位置不变也仍持续发送新时间戳。

## 字段与时钟

- 所有障碍物：`sign=1`、`type=10`、`threatLevel=2`、`targetSpeed=0`、`targetCourse=0`，且 `batch=platformId`。
- 根据用户提供的Excel，`sign=1` 表示敌，不能通用地解释为“障碍物”；`type` 文档只列0不明、1渔船、2浮标、3灯塔，实测10尚无文档定义。后续不能仅凭敌我属性或文档类型筛掉目标。
- 报文没有目标尺寸或碰撞半径字段。用户约定的80米需要在算法内部配置；艇体尺寸也由内部参数提供。
- `direction` 的协议定义依赖发现平台，而协议未提供发现平台ID。避障应使用绝对经纬度计算相对距离和方位，避免把该字段直接当成本艇测得方位。
- 协议时间戳为当天北京时间起算毫秒。发送时间相对本地接收时钟约快111.264秒，观测中基本稳定。这是两个时钟的偏移，不能当作负网络时延。信息年龄使用本地接收单调时钟；报文时间戳用于同源时序，需考虑跨午夜回绕、乱序和源端重启。

## 对后续接入的约束

1. 按单目标增量流维护缓存，逐包更新；每轮决策读取一致快照，不等待一份“完整障碍物包”。
2. 记录每个ID最后接收时间，区分正在更新、暂时失联、历史已知静态位置。停止发送不意味着障碍物在现实中消失，不应立即删除已知静态障碍物。
3. 接收层保留融合目标；决策层再按本艇位置、航线与预测风险筛选，避免用“距本艇超过5公里”作为接收有效性的硬条件。
4. 处理好未知类型和本艇排除；其他船艇同样是物理避碰对象。
5. 当前控制循环只向策略传本艇态势，Kev没有使用这些障碍物。这次导航路径不构成避障能力验证。

## 文件

- `events.jsonl`：每包本地UTC接收时间、单调经过时间、来源、目的组播、完整原始十六进制、头字段和解析状态。
- `summary.json`：停止时监听统计、各ID最新状态和最后接收年龄。
- `analysis.json`：最终离线统计和每目标更新间隔、距离、字段变化次数。
- `target-distance.png`：仅在实际收到目标新报文的时间段绘制其距本艇距离。
- `fusion-range-check.json`：最近艇距离的融合范围核对。
- `observe_first_task.py` / `analyze.py`：监听脚本快照与离线分析脚本。
- `stop-confirmation.json`：用户通知对应的停止边界与抓包限制。
